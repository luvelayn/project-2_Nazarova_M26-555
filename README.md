# Primitive DB

Учебная консольная база данных с управлением таблицами, CRUD-операциями
и хранением данных в JSON-файлах.

## Установка и запуск

Требуются Python 3.12+ и
[uv](https://docs.astral.sh/uv/getting-started/installation/).
Из корня проекта:

```bash
uv sync
uv run database
```

## Управление таблицами

- `create_table <имя> <столбец:тип> ...` — создать таблицу.
- `list_tables` — показать список таблиц.
- `drop_table <имя>` — удалить таблицу.
- `help` — показать справку.
- `exit` — выйти. Также доступны `Ctrl+C` и `Ctrl+D` при вводе команды.

Типы столбцов: только `int`, `str`, `bool` в нижнем регистре. Имена состоят из
латинских букв, цифр и символов подчёркивания; имена столбцов не должны повторяться.
Имена регистрозависимы: `Name` и `name` — разные столбцы, `Users` и `users` —
разные таблицы. Ключевые слова команд пишутся строчными буквами.
Нужно указать хотя бы один столбец. `ID:int` добавляется первым автоматически;
для таблицы только с ID укажите его явно.

Пример команд:

```text
create_table users name:str age:int is_active:bool
list_tables
drop_table users
exit
```

## CRUD-операции

- `insert into <имя> values (<значение1>, <значение2>, ...)` — добавить запись.
- `select from <имя>` — показать все записи.
- `select from <имя> where <столбец> = <значение>` — выбрать записи по условию.
- `update <имя> set <столбец> = <значение> where <столбец> = <значение>` —
  обновить записи по условию.
- `delete from <имя> where <столбец> = <значение>` — удалить записи по условию.
- `info <имя>` — показать столбцы таблицы и количество записей.

Все поля обязательны. При вставке значения передаются в порядке столбцов,
без `ID`. Для пустой таблицы первый ID равен 1, затем используется максимальный
ID среди текущих записей плюс 1. Ранее сохранённые ID не меняются.
Изменять `ID` через `update` нельзя.

Строки заключаются в двойные кавычки, целые числа передаются без кавычек.
Булевы значения принимаются в любом регистре: `true`, `True`, `TRUE`,
`false`, `False`, `FALSE`. Значение должно соответствовать типу столбца,
в том числе в условиях `where` и присваиваниях `set`.
Поддерживаются одно условие `where` с проверкой равенства (`=`) и одно
присваивание `set`.

Перед `update` и `delete` программа выбирает подходящие записи. Если совпадений
нет, выводится `Подходящие записи не найдены.`; операция и сохранение не
выполняются, подтверждение удаления не запрашивается.

Пробелы между элементами команды необязательны там, где есть разделитель:
`("Name",22)` и `( "Name" , 22 )` равнозначны. Пробелы и запятые внутри
строк сохраняются. Для кавычек внутри строки используется `\"`.
В `insert` допустима ровно одна группа значений в скобках без лишних токенов
после неё.

Пример:

```text
create_table users name:str age:int is_active:bool
insert into users values ("Ivanov, Ivan",22,TRUE)
select from users where is_active = True
update users set age = 23 where name = "Ivanov, Ivan"
delete from users where ID = 1
info users
drop_table users
exit
```

## Ошибки команд

Ошибки разбора выводятся без префикса `Ошибка:`. Это одинаково работает для
простых и сложных команд:

- неизвестная команда: `Функции unknown нет. Попробуйте снова.`;
- неверная структура: `Ожидается: info <имя_таблицы>`;
- недопустимое значение: `Некорректное значение: Ann. Попробуйте снова.`
  (например, строка без двойных кавычек).

Неверный формат описания столбца (например, `age` вместо `age:int`) — ошибка
разбора. Допустимость имён, типов и отсутствие повторяющихся имён проверяются
правилами базы после разбора команды.

Нарушения правил базы выводятся с префиксом `Ошибка:`. Например, запрос
`where age = "22"` для столбца `age:int` вызывает ошибку типа, поскольку
`"22"` — строка. Чтение и запись файлов имеют отдельное сообщение:
`Ошибка работы с файлами: ...`. После ошибки команды программа снова
запрашивает ввод. Если не удалось загрузить метаданные, программа завершается.

Ошибки операций базы обрабатываются декоратором `handle_db_errors`:
он перехватывает ошибки валидации, отсутствующие ключи и файлы, а также
непредвиденные исключения. Если декоратор обработал ошибку операции,
программа пропускает сохранение её результата и сообщение об успехе.

## Подтверждение удаления

Перед удалением таблицы или найденных записей программа запрашивает
подтверждение:

```text
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:
Вы уверены, что хотите выполнить "удаление записей"? [y/n]:
```

Для выполнения введите `y`. Любой другой ответ, а также `Ctrl+C` или `Ctrl+D`
при подтверждении отменяют операцию. При отмене метаданные, записи и файлы
остаются без изменений.

## Время выполнения и кэш запросов

Декоратор `log_time` измеряет обработку данных в `select` и `insert` с помощью
`time.monotonic()` и выводит время с точностью до трёх знаков:

```text
Функция select выполнилась за 0.001 секунд.
```

Чтение и запись файлов выполняются отдельно от этих замеров.
Результаты `select` кэшируются в памяти по имени таблицы и условию `where`.
Повторный одинаковый запрос использует готовый результат без чтения файла
записей и повторного замера функции `select`.

Кэш сбрасывается после успешных `insert`, `update`, подтверждённых `delete`
и `drop_table`. Отмена удаления сохраняет кэш. Кэш действует только в текущем
запуске.

## Хранение данных

Метаданные хранятся в `data/meta/db_meta.json`, записи — в `data/<имя>.json`
относительно директории запуска. Схема каждой таблицы хранится словарём
`{"ID": "int", "name": "str", ...}`. Для работы с той же базой запускайте
программу из одной и той же директории.

При создании таблицы её файл данных содержит пустой список `[]`.
При удалении таблицы сначала сохраняются метаданные без неё, затем удаляется
её файл данных. Если удалить файл не удалось, программа сообщает об этом.

## Разработка

Проверка кода линтером Ruff:

```bash
uv run ruff check src
```

Сборка пакета для распространения:

```bash
uv build
```

Архив исходного кода и wheel-пакет сохраняются в директории `dist/`.
